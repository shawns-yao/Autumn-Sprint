# 秋招速递

秋招速递是一套面向个人求职过程的本地优先工作台，用于集中记录公司、岗位、招聘流程、面试复盘、笔记和投递资源。

它把每一次投递拆成可追踪的步骤：投递完成后从初筛开始，经过测评、笔试、一面、二面和三面，直到 Offer。投递日期单独记录，不占用招聘流程节点。一个公司可以关联多个岗位，并可以调整岗位志愿顺序，方便在同一家公司投递多个方向时保持清晰记录。

> 整理心仪岗位，记下每一次成长。一步步走好秋招的每一程。

项目地址：<https://github.com/shawns-yao/Autumn-Sprint>

## 功能概览

- **岗位管理**：记录公司、岗位名称、城市、来源、岗位链接、投递日期和岗位 JD。
- **多岗位志愿**：同一家公司下维护多个岗位，支持新增、删除、切换和拖拽调整志愿顺序。
- **招聘流程**：默认从初筛开始，也可以在岗位详情中添加、排序和移除自定义阶段；完成当前阶段后自动推进下一阶段。
- **面试与复盘**：按招聘阶段记录安排信息、结果、标签和复盘内容，支持富文本编辑。
- **投递总览**：查看进行中、总投递、已结束和 Offer 等统计，以及流程分布、投递趋势和近期节点。
- **笔记中心**：创建、编辑、分类、标记和关联岗位笔记，保留版本冲突保护。
- **投递资源**：集中保存招聘官网、投递入口和其他实用链接。
- **附件管理**：在岗位详情中上传、预览、下载和删除简历或其他资料附件。
- **提醒与导出**：配置面试、测评和笔试提醒，并导出岗位、笔记、资源和设置数据。
- **AI 服务配置**：连接支持 OpenAI 接口格式的模型服务，并在设置页测试连接和查看可用模型。

## 页面说明

| 页面 | 用途 |

| 投递资源 | 管理招聘官网、投递页面和其他链接 |
| 设置 | 配置提醒、AI 服务和数据导出 |

- React、TypeScript、Vite

## 本地运行

### 环境要求

- Node.js 24 或兼容当前依赖的较新版本
- npm

### 安装依赖

```bash
npm ci
```

### 启动后端

在一个终端中运行：

```bash
npm run api
```

后端默认监听 `http://127.0.0.1:8787`，数据文件默认使用 `data/autumn-sprint.sqlite`。

### 启动前端

在另一个终端中运行：

```bash
npm run dev
```

打开 Vite 输出的本地地址，默认通常为 `http://localhost:5173`。

如果后端地址不是默认地址，可以在前端环境中设置 `VITE_API_BASE_URL`。

## Docker 部署

项目提供网页和 API 两个容器，数据库通过独立数据卷持久化，Caddy 负责 HTTPS 和入口认证。

1. 复制 `.env.example` 为 `.env`。
2. 设置 `DOMAIN`、`BASIC_AUTH_USER` 和 `BASIC_AUTH_PASSWORD_HASH`。
3. 如需使用 AI 服务，设置后端环境变量 `AI_API_KEY`。
4. 构建并启动：

```bash
docker compose up -d --build
```

部署前可以检查 Compose 配置：

```bash
docker compose config
```

API 只在容器网络中提供服务，网页容器对外提供 `80` 和 `443` 端口。生产环境请使用正式域名、强密码和可靠的数据卷备份策略。

## 数据与隐私

项目采用本地优先的数据保存方式。岗位、笔记、资源、提醒设置和附件默认保存在本机 SQLite 数据库中，不会自动同步到 GitHub 或其他云端服务。

以下内容属于本地运行数据，不应提交到 Git：

- `data/` 下的 SQLite 数据库、备份、导入产物和个人求职记录
- `.env` 及其他包含密钥的环境文件
- `Log/`、`Temp/` 和测试输出目录

仓库中的 `.gitignore` 已覆盖上述本地数据。提交代码前请检查 `git status`，确认没有个人岗位、JD、笔记、附件、数据库或密钥文件。

设置页的导出功能会生成包含个人求职信息的 JSON 文件，请将导出文件保存在安全位置，并避免上传到公开仓库。

## 开发约定

- 优先复用现有组件和设计系统，保持页面交互一致。
- 不在仓库中提交真实个人数据、数据库文件、附件或密钥。
- 修改数据结构或部署配置后，先执行对应的定向检查，再进行生产构建。
